### THE OVERCLAIM — why Task 0 exists (verified first-hand in this worktree)

`plugins/spec-loop/workflows/slice-wave.workflow.js` today:

```js
async function dispatch(slice, state, role, prompt, opts) {
  state.stage = role
  guard(slice, state)
  ...
```

`state.stage` is the **most recent role passed to `dispatch()`**, and it is never cleared. At
throw time it is therefore the last dispatch *started*, not the one that failed. Three of the
four throw shapes make the words "in flight" factually false:

1. **Concurrent dispatches.** `stageCritique` (`:580`) and `stageReviewGate` (`:694`) fan out
   via `parallel()`, each thunk calling `dispatch()`. A throw in the first reviewer reports
   the LAST reviewer's role.
2. **A throw between dispatches** — exactly the historical unguarded `r.commits.head`
   `TypeError` in `runTask()` that this run exists to reclassify. No agent was in flight; the
   reported stage is one that already *completed successfully*. The primary motivating
   scenario yields a literally false claim.
3. **`state.stage = role` runs BEFORE `guard(slice, state)`**, so an agent-cap or token-floor
   rejection advances the field to a role that never dispatched at all.

Yet `runSliceError()` emits title `slice crashed in ${stage}` and context
`Stage/role in flight: ${stage}`, and the same claim was written into two normative
contracts this slice shipped (`skills/escalation-gate/SKILL.md:76`,
`agents/slice-worker-fallback.md:152`). `slice-worker-fallback.md` is the behavioural spec
for the inline-mode twin, so an inline run is currently instructed to assert a stage it
cannot know — and will invent one. That reproduces the exact defect class this run was opened
against ("a catch-all wrapper reports the resulting `TypeError` as whatever it is written to
assume").

**The remedy is a WORDING fix, not a mechanism fix.** Binding constraint, verbatim: *"Do NOT
redesign stage tracking to be concurrency-accurate. The fix for the overclaim is to correct
the CLAIM in the context string and the two doc sites, not to rebuild the mechanism."* Task 0
hedges the wording, moves the one assignment that is cheap and non-architectural
(`state.stage = role` after `guard()`), and stops there.
