# Slice s3 — Tab-indentation under-count in the Python indent model

## Goal
Make the quality gate's Python **nesting/cognitive** indent model expand tabs before dividing
by the 4-column step, so a tab-indented Python file no longer reports `nesting_depth` 0 at any
real depth, and fix the one dangling CHANGELOG reference s2 left behind.

## Architecture
`quality_gate.py` derives Python indent-based metrics from `len(line) - len(line.lstrip(...))`.
The defect lives in the **three** sites that strip SPACES ONLY — `_nesting_depth_python`
(`:1076`), the `_cognitive_approx` python arm (`:1108`), and `_function_metrics` `base_indent`
(`:1164`) — where a tab contributes 0 columns and the whole file collapses to depth 0. A single
new PURE helper, `_py_indent_width(line)`, becomes the one place leading whitespace becomes a
column count; it expands the leading run with `str.expandtabs(4)` so one tab equals exactly one
step of the existing hardcoded `// 4` model. Those three sites, and only those three, call it.
No new module, no new file, no signature change on any public function.

**The two bare `lstrip()` reads inside `_extract_functions_python` (`:911`, `:917`) are NOT
part of this defect and MUST NOT be changed** — see Task 1 step 5 for the measured reason.

`plugins/spec-loop/scripts/test_quality_gate.py`, module-level fixtures, 4-space hanging
indents, no type hints, docstring on every function with `(PURE)` trailing on side-effect-free
