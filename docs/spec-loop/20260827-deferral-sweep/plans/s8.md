## Task 3 — compute section identity from the RAW record, not the truncated render

**Why (BLOCKING 2):** `_escalation_identity` compares the rendered `- Context:` and
`- The decision:` lines, which `render_escalation` has already passed through
`_one_line(..., 400)`. Two distinct rounds agreeing on their first ~399 characters therefore
collide as "the same question", and that is the common case: the controller measured 7 of the
12 recorded `escalation-opened` payloads carrying a context longer than 400 characters, and a
`quality-gate-block` context is a newline-joined findings list whose rounds differ near the
tail. Identity moves to the raw `id`, `context` and `question`.

**Scope note, because the previous reviewer got this wrong:** raw-field identity needs no
change to any truncation limit, so the "do not refactor run_state.py's truncation limits"
ceiling is untouched and this fix is IN SCOPE. **Do not change the `400`s or the `300`s.**

Because a page's existing sections are only available as rendered text, the raw identity must
be *carried on the page*. `render_escalation` emits a second HTML-comment anchor holding a
16-hex fingerprint of the raw fields, and matching compares fingerprints. A section with no
fingerprint (a page rendered before this change) yields `""`, matches no record, is never

   def escalation_identity(record):
       """A fingerprint of the fields that identify one EscalationRecord (PURE).

       Computed from the RAW id, context and question, whitespace-collapsed. A
       context longer than the render cap makes a fingerprint taken from the
       rendered lines merge distinct questions, so the raw fields are the only
       sound source. Title, options, status and answer are deliberately
       excluded: they may legitimately differ between a record and its own
       re-emit.
       """
       keys = ("id", "context", "question")
       fields = [" ".join(str(record.get(key) or "").split()) for key in keys]
       joined = "\x1f".join(fields)
       return hashlib.sha256(joined.encode("utf-8")).hexdigest()[:16]
