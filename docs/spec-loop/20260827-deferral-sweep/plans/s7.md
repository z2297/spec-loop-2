# Plan — slice s7: widen the lost-slice escalation record to three controller-named options

## Goal

Give the wave-entry lost-slice escalation record the same three controller-named options
(`Retry this slice` / `Skip this slice` / `Stop the run`) that `runSliceError` already passes,
with details honest for a slice that never ran; update the behavioural harness that currently
pins the single substituted generic option; and move the one live skill-doc clause that would
otherwise become FALSE about the shipped code onto the new behaviour.

## Architecture

`plugins/spec-loop/workflows/slice-wave.workflow.js` builds every escalation record through
`esc(slice, trigger, title, context, question, options)`, which substitutes ONE synthetic option
labelled `Proceed with the recommended default` (detail = the whole context) whenever `options`
is empty. The wave-entry fallback — the `results.map((r, i) => r || {...})` object that
synthesises a result for a slice whose `runSlice` returned nothing — passes `options: []` and so
gets that generic option, while `runSliceError` passes three explicit options. This slice changes
exactly one argument at the wave-entry call site (`[]` → a three-element array), rewrites the
harness test that pinned the old shape, and rewrites the one clause in
`plugins/spec-loop/skills/escalation-gate/SKILL.md` that asserts the old single-option shape in
the present tense. No change to `esc()`, no change to the id scheme, no change to the record's
context or question.

## Tech stack

Node ESM workflow file (`.workflow.js`, loaded by the Workflow host as an async function body),
driven in tests by `node:test` + `node:assert/strict` via the mock host sandbox in
`plugins/spec-loop/scripts/slice_wave_harness.mjs`. Zero dependencies. Python suites unchanged.
Skill docs are plain Markdown and are INVISIBLE to the quality gate (`_lang_for` returns `None`
for unknown extensions), so Task 3 adds zero gate exposure.
