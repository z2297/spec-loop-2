# Slice s6 — Round 2 (NARROW): stop the brace scan mask from silently under-counting

## Goal

Fix exactly three round-2 findings in the accepted brace-language scan mask: restrict the
hand scanner to the JS/TypeScript family so a Rust lifetime or a C++ digit separator can no
longer pair into a phantom string over real code, replace the false "odd quote count forces a

is NOT line-bounded), and widen the test module's stale docstring.

## Architecture

`plugins/spec-loop/scripts/quality_gate.py` derives a heuristic language family from a file
extension (`_lang_for` over `_EXT_LANG`) and uses it for two different jobs: choosing the
extraction/nesting model, and choosing the scan mask handed to `_branch_count` /
`_cognitive_approx`. Those two jobs are currently welded to the same `"cbrace"` value, so
every brace extension gets a mask lexed with JS quoting rules. This slice separates them: a
new `_scan_lang_for(path)` returns the MASK language (`"python"`, `"js"`, or `None` for raw),
while `_lang_for` keeps serving extraction and nesting untouched. Nothing else in the seam
moves — the scanner, the template-literal handling, the corruption guard and the differential
harness all stand.

## Tech stack

Python 3 standard library only (`re`, `os`, `tokenize`, `unittest`, `unittest.mock`). No new
dependencies, no new files.
