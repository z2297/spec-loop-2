# Plan — s1: `refactor_radius` config block + key-wise overlay merge + command docs

**Goal.** Add a `refactor_radius` configuration block to the quality-gate config with
conservative default-ON values, make the per-repo overlay merge it **key-wise** (not
wholesale), and document it in `plugins/spec-loop/commands/quality-gate.md` at both the
step-1 key list and the written schema.

**Architecture.** `plugins/spec-loop/scripts/quality_gate.py` is the single door to the
effective quality-gate configuration (`load_config(path, overlay_path)` → `--print-config`).
Today it merges `thresholds` key-wise, concatenates `custom_gates`, unions `tier3_surfaces`,
and `dict.update()`s everything else — so a brand-new block placed in a repo overlay would
**replace** the global block wholesale, silently dropping every sibling key. This slice adds
`DEFAULT_REFACTOR_RADIUS`, one shared validation helper `_radius_object()`, key-wise merge in
both the overlay branch and the defaults branch, and the operator-facing documentation. It
adds **no measurement, no evaluation, and no comparison** — later slices in this run consume
the block through `ctx`; this slice only makes the numbers exist, survive an overlay, and be
discoverable.

**Tech stack.** Python 3 standard library only (no third-party, no type hints in
`quality_gate.py` — match the file). Tests are stdlib `unittest`. Markdown for the command doc.

## Semantics of the block (fixed here; consumed by later slices)

`refactor_radius` is the **planner-declared, pre-execution proxy** for how much existing code a
slice's plan intends to rewrite. It is not a measured diff. The block:

```json
"refactor_radius": {
  "enabled": true,
  "max_rewrite_ratio": 0.5,
  "max_touched_existing_files": 8,
  "min_rewritten_lines": 150
}
```

- `enabled` (bool, default `true`) — ships **default-ON**.
- `max_rewrite_ratio` (number, default `0.5`) — declared rewritten-existing-lines ÷ total
  declared changed lines.
- `max_touched_existing_files` (integer, default `8`) — count of pre-existing files the plan
  declares it will modify.
- `min_rewritten_lines` (integer, default `150`) — noise floor: below this many declared
  rewritten lines the radius check does not fire at all, so a 0.9 ratio over 12 lines is not a
  halt.

Intended (later-slice) firing rule, recorded here so the doc and the defaults agree: fire when
the floor is met **and** either maximum is exceeded. **This slice implements none of that** —
no comparison, no evaluation, no event. It only defines, merges, and documents the numbers.
Absent or non-numeric values are a "not measured" state for the consumer, never coerced.

def _radius_object(value, what):
    """Coerce a raw `refactor_radius` config value to a plain dict. (PURE)

    An absent block yields {} so the defaults stand. A PRESENT non-object is a
    hard error rather than a silently ignored value: dropping a list or a bare

    if value is None:

    return dict(value)
