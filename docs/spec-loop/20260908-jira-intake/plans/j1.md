# Plan — slice j1: Jira read lane (`jira_client.py`)

**Goal.** Add a self-contained, stdlib-only, READ-ONLY module
`plugins/spec-loop/scripts/jira_client.py` that resolves one Jira issue key to a normalized
JSON record (key, summary, description, acceptance criteria, status, issue type, web url, and
the FULL paginated comment list), authenticating with HTTP Basic auth built from
`JIRA_BASE_URL` / `JIRA_EMAIL` / `JIRA_API_TOKEN`, failing closed with an actionable message
when any is unset, and registered in the coverage gate.

**Architecture.** The module is a line-for-line sibling of
`plugins/spec-loop/scripts/pr_resolver.py`: one `_http_get` that is structurally incapable of
issuing a mutating verb, an env-var credential read with a fail-closed actionable message
(mirroring `pr_resolver.py:324-329`), strict regex allow-lists on every untrusted value before
it reaches a URL, and a single `_normalized()` builder so the inter-slice JSON contract shape
cannot drift. Resolution is three read-only GETs against Jira Cloud REST v3 — the field
catalogue (best-effort, to locate an "Acceptance Criteria" custom field), the issue itself, and
a `startAt`-paginated sweep of `/comment` — rendered from Atlassian Document Format into plain
text by a pure `adf_to_text()` walker. Nothing in this slice writes to Jira, writes to disk, or
touches the loop.

**Tech stack.** Python 3 standard library only (`argparse`, `base64`, `json`, `os`, `re`,
`sys`, `urllib.parse`, `urllib.request`, `urllib.error`). Tests are stdlib `unittest` with
`unittest.mock`. No network in tests, ever.

## Verified REST v3 facts (checked live against Atlassian docs on 2026-09-08 — do not re-derive from memory)

Source pages fetched during planning:
`https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-comments/`,
`.../api-group-issues/`, and
`https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/`.

1. **Auth.** Basic, not Bearer. Header is `Authorization: Basic <base64("email:api_token")>`.
   (Basic-auth page: "Build a string of the form `useremail:api_token`. BASE64 encode the
   string. Supply an Authorization header with content `Basic` followed by the encoded string.")
2. **Get issue.** `GET /rest/api/3/issue/{issueIdOrKey}`; query parameter `fields` is an
   array<string> (comma-separated). Response is an `IssueBean`: `{"key":..., "fields":
   {"summary":..., "description": <ADF doc or null>, "status": {"name":...},
   "issuetype": {"name":...}, "<customfield_id>": ...}}`.
3. **Get comments.** `GET /rest/api/3/issue/{issueIdOrKey}/comment`; query parameters
   `startAt`, `maxResults`, `orderBy`, `expand`. Response is a `PageOfComments`:
   `{"startAt": int, "maxResults": int, "total": int, "comments": [ ... ]}` — note the page key
   is **`comments`**, NOT `values` (`values` is the shape of the *other* endpoint,
   `POST /rest/api/3/comment/list`, which returns a `PageBeanComment`). Each comment is
   `{"id": "10000", "author": {"displayName":..., "accountId":...}, "body": <ADF doc>,
   "created": "2021-01-17T12:34:00.000+0000", "updated": ...}`. The server default
   `maxResults` is 50, so an unpaginated read silently truncates a chatty card.
4. **ADF.** On `/rest/api/3`, `description` and each comment `body` are Atlassian Document
   Format objects: `{"type": "doc", "version": 1, "content": [ {"type": "paragraph",
   "content": [{"type": "text", "text": "..."}]} ]}` — not strings. (The comment POST body also
   requires an ADF doc; that is a later slice's problem, recorded here only so the renderer is
   built with both directions in mind. **Do not add a POST in this slice.**)
5. **Field catalogue.** `GET /rest/api/3/field` returns a flat array of
   `{"id": "customfield_10039", "key":..., "name": "Acceptance Criteria", "custom": true, ...}`.
   Used to locate the AC custom field by display name.

## Design decisions (made here; implementers do not re-litigate)

- **Host allow-list.** `JIRA_BASE_URL` must be `https` and its hostname must match
  `^[A-Za-z0-9][A-Za-z0-9-]{0,60}\.(atlassian\.net|jira\.com)$`. Jira Data Center / on-prem
  hosts are out of scope for this slice; adding an opt-in extra-hosts env var is deliberately
  NOT done (it would re-open the exact hole the allow-list closes). Anything else fails closed.
- **Redirects are refused outright**, not followed-with-header-stripped. A custom
  `urllib.request.HTTPRedirectHandler` subclass whose `redirect_request` returns `None` makes
  urllib raise on 3xx; the module builds one module-level opener from it. This is simpler to
  prove than header stripping and is allowed explicitly by the constraint.
- **Acceptance criteria** are resolved in a fixed two-step order and the winner is recorded in
  the record: (1) the value of a custom field whose catalogue `name` casefolds to
  `"acceptance criteria"`, if such a field exists and its value is non-empty →
  `acceptance_criteria_source == "field"`; else (2) the section of the rendered description
  under an `Acceptance Criteria` heading → `..._source == "description"`; else `""` and
  `..._source == ""`. The catalogue GET is **best-effort**: a failure (commonly a 403 on a
  locked-down site) degrades to path (2) rather than failing the resolve, because the field is
  optional and its provenance is recorded. Every other GET is fail-closed.
- **Empty-field policy.** `key`, `summary`, `status`, `issue_type`, `web_url` are required and
  non-empty; an empty one is a half-resolve and raises (mirrors `pr_resolver._normalized`).
  `description`, `acceptance_criteria`, `acceptance_criteria_source` and an empty `comments`
  list are all legitimately empty.
- **Exit codes** follow the conventions' two-exception pattern: `JiraUsageError` → 2 (bad key,
  bad/absent base URL, missing credentials — anything the user can fix in their invocation or
  environment); `JiraError` → 1 (contract failure: HTTP error, malformed JSON, half-resolve).
- **No subprocess, no filesystem writes, no `datetime`** anywhere in the module.

```python
def validate_issue_key(key):
    """Validate an UNTRUSTED Jira issue key before it reaches a URL segment.
    Rejects lowercase, path separators, a leading '-' (argument injection) and
    anything else outside ISSUE_KEY_RE."""
    if not ISSUE_KEY_RE.match(key or ""):
        raise JiraUsageError(
            f"invalid Jira issue key {key!r}: must match {ISSUE_KEY_RE.pattern} "
            "(an uppercase project key, a hyphen, then digits -- e.g. A-1 or PROJ-42)"
        )
    return key
```

```python
class _NoRedirect(urllib.request.HTTPRedirectHandler):
    """Refuse every 3xx. The base URL is user-supplied, so pr_resolver's
    hardcoded-origin property is gone: following a redirect could replay the
    Authorization header to another origin. Returning None makes urllib raise
    the HTTPError instead of following it."""

    def redirect_request(self, req, fp, code, msg, headers, newurl):
        """Return None so urllib treats the 3xx as a terminal error."""
        return None


_OPENER = urllib.request.build_opener(_NoRedirect)

CRED_VARS = ("JIRA_BASE_URL", "JIRA_EMAIL", "JIRA_API_TOKEN")


def credentials():
    """Read the Jira credentials from the ENVIRONMENT ONLY and fail closed with
    an actionable message when any is unset. Never read from argv: argv is
    visible in `ps` and lands in shell history."""
    values = {name: (os.environ.get(name) or "").strip() for name in CRED_VARS}
    missing = [name for name in CRED_VARS if not values[name]]
    if missing:
        raise JiraUsageError(
            "Jira access requires the environment variable(s) "
            + ", ".join(missing)
            + ". Set JIRA_BASE_URL to your site origin (e.g. "
            "https://your-site.atlassian.net), JIRA_EMAIL to your Atlassian "
            "account email, and JIRA_API_TOKEN to an API token created at "
            "https://id.atlassian.com/manage-profile/security/api-tokens. "
            "Pass them in the environment, never on the command line."
        )
    return (validate_base_url(values["JIRA_BASE_URL"]),
            values["JIRA_EMAIL"], values["JIRA_API_TOKEN"])


def _auth_header(email, token):
    """Build the Jira Cloud Basic auth header: base64("email:api_token").
    Verified against Atlassian's basic-auth-for-rest-apis page (2026-09-08) --
    Jira Cloud REST v3 uses Basic with an API token, NOT Bearer."""
    raw = f"{email}:{token}".encode("utf-8")
    return "Basic " + base64.b64encode(raw).decode("ascii")


def _http_get(url, email, token):
    """HTTP GET via the no-redirect opener (READ-ONLY: never sets a body and
    never a mutating method). The sole network entry point in this module.
    Errors reference only the URL -- the credentials ride in a header, so
    neither the token, the email, nor the composed base64 pair can appear in an
    exception message."""
    req = urllib.request.Request(
        url,
        headers={"Authorization": _auth_header(email, token),
                 "Accept": "application/json"},
        method="GET",
    )
    try:
        with _OPENER.open(req, timeout=30) as resp:
            return resp.read()
    except urllib.error.HTTPError as exc:
        raise JiraError(f"HTTP {exc.code} fetching {url}: {exc.reason}") from exc
    except urllib.error.URLError as exc:
        raise JiraError(f"network error fetching {url}: {exc.reason}") from exc


def _parse_json(raw, what):
    """json.loads with an actionable JiraError, so a malformed response fails
    with a clear message rather than a raw traceback."""
    try:
        return json.loads(raw)
    except json.JSONDecodeError as exc:
        raise JiraError(
            f"Jira returned a {what} response that is not valid JSON ({exc})"
        ) from exc
```
