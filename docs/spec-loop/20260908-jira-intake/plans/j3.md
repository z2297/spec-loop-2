# Plan — slice j3: documentation-accuracy fix in `jira-intake.md`

## Goal

Correct the two recovery sentences in `plugins/spec-loop/commands/jira-intake.md` that wrongly
tell an operator to re-run the whole slash command after a partial post, and name the
cross-process race in the security section — with doctrine pins so the corrected wording cannot
silently regress.

## Architecture

`plugins/spec-loop/commands/jira-intake.md` is a Claude Code slash-command markdown file: its
prose IS the runtime contract for the intake lane, so a false sentence in it is a real defect
even though no Python changes. `plugins/spec-loop/scripts/test_doctrine_jira_intake.py` pins
load-bearing phrases from that file with one-directional `assertIn` substring assertions over a
whitespace-normalised copy of the text. This slice changes prose in the command file and adds
matching pins in the existing doctrine test classes. **No Python behaviour changes at all.**

## Tech stack

Markdown (command prose) + stdlib Python `unittest` (doctrine substring assertions). Python 3.12,
no third-party imports.

## Global Constraints (verbatim, binding on every task)

- Stdlib-only Python. No third-party imports.
- Tests are stdlib unittest, not pytest.
- Controller owns the clock. comment_marker deliberately does NOT hash the timestamp so a re-run with the SAME payload reproduces the same marker - preserve that exactly.
- Credentials from the environment only. The token, the email, and base64(email:token) must be absent from exception text, stdout and stderr.
- Do not weaken fetch_comments' fail-closed 'total' guard and do not loosen _http_get.
- Quality-gate precedent: whole-file class_lines breaches are ACCEPTED pre-existing debt; a function-level violation in new code is a genuine block. Keep new functions at nesting_depth <= 3, parameter_count <= 4, cognitive <= 15, cyclomatic <= 10.
- The intake command must remain structurally incapable of starting the loop: no Workflow and no Edit in allowed-tools.

### Scope ceiling (do NOT build)

The write lane and its duplicate-marker refusal are built, committed and controller-verified. Do
not re-plan the lane, rewrite `jira_client.py`, or re-derive committed work. No Jira write other
than adding a comment; no per-write re-read of the card's comments; no local ledger as the dedupe
gate; do not re-open the whole-file `class_lines` gate failures; do not change `_comment_results`'
`by_marker` collapse; do not touch the wave engine or the run-state contract.

## Task 1 — Rewrite the two false recovery sentences in Step 8

**Lane:** `judgment` (the exact wording is the deliverable and must be both true and precise about
what may be re-run).

**Files**
- Modify: `plugins/spec-loop/commands/jira-intake.md:180-192`

**Interfaces**
- Consumes: nothing.
- Produces (exact literal substrings that Task 3 pins; whitespace-normalised, em dashes as
  authored):
  - `re-run the POSTING step with the same rendered comments file`
  - `do NOT re-run the refinement`
  - `a regenerated refinement produces new markers`

**Context — why the current text is false.** `comment_marker` hashes `key + kind + payload`, and
the payload is model-regenerated refinement text. Measured on this branch: payload
`The API must return 200.` yields `[spec-loop-intake:understanding:7e7cb8d75622]`; the same
sentence without its final period yields `[spec-loop-intake:understanding:875bd6c89404]`. One
character of drift is a dedupe miss and therefore a second near-identical comment on a live card.
Re-running the whole slash command re-runs the refinement, so it is NOT a no-op. Re-running only
the posting step with the SAME `<tmp>/comments.json` IS.

**Steps**
1. Open `plugins/spec-loop/commands/jira-intake.md` and locate the sentence at ~:182 ending
   `...skipped rather than duplicated, and a re-run of this whole command is a genuine no-op.`
2. Replace the clause `and a re-run of this whole command is a genuine no-op` with:
   `and re-running the POSTING step with the same rendered comments file is a genuine no-op`.
   Leave the rest of that sentence, including the preceding `ONCE, before the first write of the
   run — not before each individual comment —` wording, byte-identical.
3. Locate the sentence at ~:190 beginning `**The correct recovery is to re-run this command**,`
   and running through `Do not post the remaining comments by hand.` Replace that whole span
   (three source lines) with:

   ```
   **The correct recovery is to re-run the POSTING step with the same rendered comments file** —
   the same `<tmp>/comments.json`, re-armed with `--post` — which the marker dedupe makes safe:
   the already-live comments come back as `already-posted` and only the remaining ones are
   written. **Do NOT re-run the refinement** (and so do not re-run this whole slash command to
   recover): a regenerated refinement produces new markers that will not dedupe against what is
   already on the card, because `comment_marker` hashes the payload text and a single character of
   drift yields a different marker and a second near-identical comment. Do not post the remaining
   comments by hand.
   ```
   Keep the existing three-space list-continuation indent used by the surrounding Step 8 lines.
4. Re-read lines 178-196 and confirm no other sentence still claims that re-running the whole
   command is safe, and that the `--post` fenced block above is unchanged.

Expected: exactly one `genuine no-op` hit, now reading `re-running the POSTING step with the same

**Lane:** `standard` (one bullet, placed beside an existing sibling bullet in the same voice).

**Files**
- Modify: `plugins/spec-loop/commands/jira-intake.md:63-68` (insert immediately after this bullet)

**Interfaces**
- Consumes: nothing (independent of Task 1's span).
- Produces (exact literal substring Task 3 pins): `read once per invocation`

**Steps**
1. Find the bullet starting at :63, `- **Known, fail-safe limitation: a quoted marker reads as
   posted.**`, and its final line `untrusted comment text, would make untrusted card content
   decide whether a write happens.` (:68).
2. Insert directly after that line, as a new sibling bullet at the same indent, before the blank
   line preceding `## Steps`:

   ```
   - **Known limitation: the dedupe gate is per-invocation, not cross-process.** The card's
     comment list is read once per invocation, before the first write, so two operators arming the
     lane concurrently — or a re-run overlapping a slow first run — can both act on the same
     pre-write snapshot and both post. Jira offers no compare-and-set on comment creation, so the
     window is accepted rather than closed; arm this lane one operator at a time, and if two runs
     did overlap, read the card before arming again.
   ```
3. Confirm the blank line before `## Steps` still exists and the bullet list renders as one list.
